Introduction

Everything you need to get blaid running well in your server.

blaid is an all-in-one Discord app: moderation and security, leveling, tickets, VoiceMaster, giveaways, Last.fm, economy, image editing, and a growing set of automation tools, all in one bot. It's built to replace several single-purpose bots with one consistent, well-documented one.

Every command on this site is pulled directly from the bot's own code, so what you see here always matches what's actually running - nothing here is hand-written documentation that can drift out of date.

Run ,help in your server for an interactive command list, or browse everything with search on the Commands page.

Server Setup

Run ,setup with Administrator permissions. This is the one command that needs to happen before most moderation features will work. It creates:

A jailed role and a jail channel only that role can see, a dedicated logs channel that every moderation action gets reported to, and a category that holds both of those channels so they stay organized and out of the way of your regular channels.

blaid's own role has to sit above every role it needs to manage - the jailed role included. If setup can't finish because of that, it tells you exactly which role to drag blaid above in Server Settings, then you just run ,setup again.

Made a mistake or want to start over? ,setup reset tears everything back down cleanly: it unjails anyone currently jailed, deletes the jail role, and removes the channels and category, so you can run ,setup fresh.

Prefixes

The default prefix is ,. Server admins can change the server-wide prefix, and any member can additionally set their own personal prefix that works for them specifically in every server blaid is in - handy if the server prefix clashes with another bot you use.

Antinuke

Set restrictions on your staff to prevent harm from being done on your server.

What is antinuke?

Antinuke automatically limits how many destructive actions your staff can take. If a staff member exceeds a threshold, they're punished automatically and your server stays safe from a compromised or malicious admin account.

The server owner and whitelisted users are always exempt. Antinuke tracks actions in a rolling window per user, per action type - each staff member has their own counter for bans, kicks, and so on. Antinuke has to be turned on explicitly, and each module is configured separately.

Available punishments: ban, kick, timeout, strip (removes only dangerous roles), staffstrip (removes only staff roles), and jail. Antinuke never deletes messages - it only blocks the action and punishes whoever tried it.

Antinuke admins

By default, only the server owner can change the antinuke configuration. You can add other trusted staff as antinuke admins so they can manage it too.

,antinuke admin (@user)

This is a sensitive command - it lets that user fully reconfigure antinuke. Run the same command again to remove someone as an admin.

,antinuke admins

Lists every current antinuke admin.

Whitelisting

Everyone is subject to antinuke by default. Whitelist a user to exempt them entirely.

,antinuke whitelist (user)

Run the same command again to remove them from the whitelist.

,antinuke list

Shows everyone currently whitelisted.

Configuring antinuke

Use ,antinuke at any time to see the current settings. Turn it on first:

,antinuke enable

Then configure each module you want protected, and set its punishment and threshold. A higher threshold means someone has to do more of that action before it triggers.

,antinuke (module) (status) (punishment) ,antinuke (module) threshold (threshold)

Check any module's current settings with ,antinuke (module).

Antiraid

Automatically detect potential raids and ongoing raids.

Configuring antiraid

Turn it on with ,antiraid toggle on. Unlike antinuke, anyone with the Administrator permission can configure antiraid, not just the owner or antinuke admins. The server owner and whitelisted users are always exempt from enforcement.

Modules

Antiraid watches join events across several modules, each with its own threshold and action: Mass Join, New Accounts, Avatar, Username, Mass Mention, and Unverified Bots.

,antiraid (module) [status] ,antiraid (module) threshold (value) ,antiraid (module) (status) (action)

Lockdown state

If your server is actively being raided, you can manually flip on lockdown to restrict access immediately, without waiting for a module to trigger.

,antiraid state

Whitelisting

Exempt specific users or roles from antiraid entirely.

,antiraid whitelist [user]

Run the same command again to remove them.

Automod

Automatic message and word filtering, so your team isn't watching chat 24/7.

Add words or phrases to the filter and blaid removes matching messages on sight, no moderator needed.

,filter add (word)

Run this during ,setup's quick-start flow to get moderation started automatically from day one.

Moderation

The full toolkit: bans (including a hardban that also deletes recent message history, and a softban that bans-then-unbans purely to clear messages), kicks, timeouts, warnings with a full history you can review later, and jail - a role-based mute that removes access to the whole server except one channel, for when a timeout isn't enough but a ban is too much.

Every action - who did what, to whom, and why - is written to your configured logs channel automatically, with a running case number so nothing gets lost. Run ,history [member] to see everything on record for someone.

,purge covers bulk deletion with over 20 filters (bots, humans, embeds, links, invites, images, and more), and ,lockdown/,unlock handle locking channels down during an incident.

Want a message customized differently than the default when someone gets punished? ,invoke lets you set your own DM or channel message per command, with variables like {user.mention} and {custom.reason}.

Fake Permissions

Grant virtual permissions to roles to allow usage of specific blaid commands.

What are Fake Permissions?

Fake permissions let you grant "virtual" permissions to a role - members with that role can use blaid commands that normally require a specific Discord permission (like Manage Guild or Kick Members), without actually having that permission on Discord itself.

This only affects blaid's own command checks - it doesn't grant real Discord permissions and has no effect on any other bot. Be careful: granting something like ban_members or kick_members lets that role use those commands entirely outside Discord's own permission oversight. Fake permissions persist across restarts.

Adding and removing

,fakepermissions add (role) (permissions)

Add multiple permissions at once by separating them with commas.

,fakepermissions remove (role)

Managing configurations

,fakepermissions list

View every role and its fake permissions.

,fakepermissions reset

Removes every fake permission in the server at once.

Honeypot

Automatically punish users who post in a honeypot trap channel.

Overview

A honeypot is a decoy channel that catches anyone who posts in it - designed to snag compromised accounts, selfbots, and spam bots that ignore channel permissions. blaid can ban, kick, or softban the offender, and optionally purge their recent messages.

Getting started

,honeypot setup

Creates a channel named "honeypot" and arms it. blaid needs Manage Channels, Ban Members, Kick Members, and Manage Messages to work. The channel has no permission overwrites by default - hide it from regular members yourself using Discord's own permission system, so only someone who shouldn't see it (a compromised account, a raid bot) would ever post there.

Configuration

,honeypot config ,honeypot action (ban|kick|softban) ,honeypot history (days) ,honeypot logs (channel) ,honeypot disable ,honeypot remove

Troubleshooting

Honeypots only trigger on an actual message - someone who can see the channel but never posts won't trip it. blaid's role also has to sit above the offender's highest role to actually punish them; if it can't, the action silently fails but the attempt is still logged.

Verification & Recovery

Hold risky new accounts for review, and put a server back together after a raid.

The verification gate

New members can be held in a quarantine role until a moderator reviews them - rather than being let in immediately or kicked automatically.

,verification setup (channel) [threshold] ,verification off

,verification setup creates the quarantine role for you and locks it out of every existing channel except the review channel you give it. Accounts younger than the threshold (in days) get the role and are posted in that channel for a moderator to ,verification approve or ,verification deny.

Channels created after setup aren't covered automatically - deny the quarantine role View Channel on new channels, or run ,verification setup again to re-lock everything.

Raid recovery

Coming soon - not yet available in blaid.

The plan: automatic periodic backups and a ,recover command that rebuilds missing channels and roles after a raid, merge-only so it never deletes or overwrites anything that survived. Until then, ,backup create and ,backup restore cover manual backup and restore today.

Welcome

Send a message to a channel automatically whenever someone joins your server - either a plain sentence, or a full custom embed built with blaid's scripting syntax (title, description, color, image, and buttons).

Variables like {user.mention}, {guild.name}, and {guild.member_count} get filled in automatically, so the same message works for every new member without editing it each time.

,welcome channel (channel) ,welcome message (text or embed script) ,welcome test ,welcome disable

Leave

The same idea as Welcome, but triggered when a member leaves the server - same channel/message/test/disable commands, same variable and scripting support. Useful for a simple goodbye message, or just a quiet log of who left and when.

,leave channel (channel) ,leave message (text or embed script) ,leave test ,leave disable

Join DM

DMs new members automatically when they join - separate from the in-server Welcome message, and sent privately instead of posted in a channel. Useful for rules, a link to a verification form, or just a personal hello that doesn't clutter a public channel.

If a member has DMs closed, the send simply fails silently for them - nothing else in the join flow is affected.

,joindm config ,joindm message (text or embed script) ,joindm toggle ,joindm test

Boost

Thank members automatically the moment they boost your server, with the same scripting and variable support as Welcome - mention the booster, show the new boost count, whatever fits your server's tone.

,boost channel (channel) ,boost message (text or embed script) ,boost test

Automation > Messages

"Messages" under Automation groups the message-based automation tools together in the sidebar. The actual tools live under their own pages: Sticky Messages, Auto Responder, and Timers.

AutoPFP

Posts a fresh image to a channel automatically on whatever interval you set - currently sources cat images from TheCatAPI. (Anime sources were tried and dropped: PebbleHost's shared hosting IP got blocked by every free anime image API tested - a hosting limitation, not a feature choice, and it can come back if hosting ever moves to a dedicated IP.)

,autopfp add (channel) ,autopfp interval (minutes) ,autopfp list ,autopfp remove (channel) ,autopfp test

Requires Administrator permission to configure.

Scheduled Posts

Schedule a message to go out at a specific future time, using the same embed scripting as welcome/leave/boost messages - useful for announcing something ahead of time without needing to be online when it should post.

Auto Roles

Automatically gives one or more roles to every new member the moment they join - no manual assignment needed. Useful for a base "Member" role, an unverified/pending role feeding into Verification, or any role everyone should start with.

,autorole add (role) ,autorole remove (role) ,autorole list

Booster Roles

Lets anyone currently boosting your server create their own personal role - their own name and color, shown just above the regular member roles. The role is automatically removed the moment they stop boosting, so it never becomes an orphaned permanent role.

,boosterrole create (name) (color) ,boosterrole rename (name) ,boosterrole color (color) ,boosterrole remove

Reaction Roles

React to a specific message with a specific emoji to get a role - remove the reaction and the role comes back off. Set up as many emoji/role pairs on the same message as you need, so one message can offer a whole menu of self-assignable roles.

,reactionrole add (message) (emoji) (role) ,reactionrole remove (message) (emoji) ,reactionrole list

Button Roles

The button-based alternative to Reaction Roles - members click a button under a message to toggle a role on or off, instead of reacting. Functionally the same idea, just a cleaner interface that doesn't clutter the message with emoji reactions.

,buttonrole add (message) (label) (role) ,buttonrole remove (message) (label) ,buttonrole list

Vanity & Server Tag

Reward members who help promote your server. Two separate signals: putting your server's vanity invite (e.g. discord.gg/yourserver) somewhere in their custom status, or equipping your server's official server tag on their profile. Either one awards a configured role automatically and posts a thank-you message.

,vanity channel (channel) ,vanity set (pattern) ,vanity role add (role) ,badge toggle ,badge channel (channel) ,badge role add (role)

Vanity requires the Presence intent to be enabled (already on for blaid), since it reads members' custom status text.

Sticky Messages

Coming soon - not yet available in blaid.

A message that stays pinned to the bottom of a channel, automatically re-posting itself after new messages push it up - useful for rules or an FAQ that should always be visible.

Auto Responder

Set a trigger phrase and blaid replies automatically whenever it appears anywhere in chat, no command needed from the member - plain text or a full embed response, with the same scripting system used throughout the bot, so a response can mention the trigger's author or link somewhere relevant.

,autoresponder add (trigger) (response or embed script) ,autoresponder remove (trigger) ,autoresponder list

Server Premium raises the number of autoresponders you can have configured at once.

Timers

Personal reminders that DM or ping you back after a set duration.

,reminder (duration) [description] ,reminder list ,reminder remove (index)

VoiceMaster

Join-to-create voice channels: members join a designated channel and blaid instantly makes them their own temporary voice channel, which they fully control.

,voicemaster setup

Sets up the category, the "Join To Create" channel, and an interface channel with buttons for Lock, Unlock, Hide, Rename, Claim, Limit, and Delete. Renaming the Join To Create channel afterward is safe - blaid tracks it by ID, not by name.

Levels

Members earn XP from chatting and level up over time, with configurable role rewards at specific levels and a fully custom level-up card image.

,rank [member] ,leaderboard

Retention

See how many new members actually stick around: how many spoke at least once after joining, and how many are still in the server.

,funnel [days]

Bump Reminder

Automatically thanks whoever bumps your server on Disboard, then reminds the server when it's time to bump again - tracks Disboard's real 2-hour cooldown, plus a leaderboard of who's bumped the most.

,bumpreminder enable [channel] ,bumpreminder thankyou [message] ,bumpreminder reminder [message] ,bumpreminder leaderboard

Reaction Triggers

Automatically react to any message containing a keyword you configure - no command from members needed, blaid just watches chat and reacts the moment a match appears. Different from Auto Responder: this only adds a reaction, it never sends a message of its own.

,autoreact add (keyword) (emoji) ,autoreact remove (keyword) ,autoreact list

Command Aliases

Create your own custom shortcut names for any existing blaid command, server-wide - useful if your team is used to a different word for something, or you want a shorter version of a long command name that everyone in your server can use.

Command Permissions

Turn individual commands on or off per server, per channel, or per role with ,disable/,enable - useful for turning off a command entirely in one specific channel, or restricting a risky command to a specific role without changing real Discord permissions.

,disable (command) ,disable (command) #channel ,disable (command) @role ,enable (command)

See also Fake Permissions for the reverse case: granting access to a command without the underlying Discord permission it normally requires.

Custom Scripts

The scripting syntax that powers welcome/leave/boost/join DM messages, ticket panels, and the standalone ,createembed command - one consistent way to build a custom embed or message anywhere blaid supports it. See the full syntax breakdown under Resources > Embeds.

Username Tracking

blaid keeps a history of every name change it sees for a member, so staff can look back at previous usernames.

,namehistory [member]

Logging

Sends a log embed to a configured channel automatically for moderation actions and server events - bans, kicks, warns, timeouts, jails, lockdowns, and more - so staff have a running record without needing to watch every channel manually. This is the same logs channel ,setup creates for you automatically.

,history [member]

Shows everything on record for a specific member, pulled from the same log.

Tickets

Fully configurable support ticket panels - single-button or dropdown with multiple ticket types, each with its own category, support roles, claim/close behavior, custom form questions, and automated messages.

Build a panel visually at blaid.best/tickets - log in with Discord, pick your server, and design Panel, Forms, and Options separately with a live preview, no commands needed.

Confessions

Anonymous confession submissions posted to a designated channel, with the submitter's identity never revealed.

Backups

Snapshot your server's roles, categories, channels, and settings, and restore from one later.

,backup create ,backup list ,backup view (name) ,backup restore (name)

Restore supports two modes: merge (only adds back what's missing, leaves everything else alone) or destructive (wipes the server back to exactly the backup state, with a confirmation step first).

Discovery

How people find blaid: our own website, Discord's built-in App Directory, and third-party bot listing sites. This isn't a server-configurable feature - just where to look if you want to see blaid's public listing or leave a review.

Music

Play audio in a voice channel from common sources - queue up multiple tracks, skip, pause/resume, and adjust volume, with the current queue visible at any time.

Giveaways

Run timed giveaways with reaction-based entry. blaid picks a winner automatically when the timer ends, and if a winner doesn't claim their prize, you can reroll for a new one without starting over.

,giveaway start (duration) (prize) ,giveaway reroll (message) ,giveaway end (message)

Last.fm

A full Last.fm integration: what you're currently listening to, top tracks/albums/artists, collages, "whoknows" server leaderboards for a given artist, crowns, taste comparisons with other members, and a full recap of your year.

,fm ,lastfm whoknows (artist) ,lastfm collage ,lastfm recap

Economy

A full server economy: wallet and bank balances, ,daily, ,work, ,crime, and ,rob for earning (and losing) money, a server ,shop, and 12 games including blackjack, crash, slots, roulette, and dice.

,balance [member] ,daily ,leaderboard

Fun

Games and lighthearted commands: Tic-Tac-Toe and BlackTea (a word-and-letters party game with lives and a countdown), plus a set of "how much/how many" novelty commands.

,tictactoe (opponent) ,blacktea

Social Lookups & Feeds

Automatic notifications when someone you configure goes live on Twitch or posts a new video on YouTube - posted straight to a channel you choose, with the streamer/creator's name, title, and thumbnail.

Image Editing

Dozens of avatar manipulation effects, all pure code (no image assets needed) - blur, glitch, gameboy palette, invert, pixelate, dizzy swirl, neon edges, and many more. Run any of them on yourself or another member.

General-purpose tools that don't fit a bigger category. Information

Embeds

blaid's own script syntax builds a full embed (or plain message) from a block of text - used for welcome/leave/boost messages, tickets, and the standalone ,createembed command.

{embed} {title: Some Title} {description: Some description} {color: #5865F2} {thumbnail: (url)} {image: (url)} {footer: text && icon_url} {author: name:X && icon:Y && url:Z} {field: Name && Value && inline} {button: label:X && url:Y && emoji:Z}

Multiple {button: ...} lines add multiple buttons to the same message. Everything supports the variables below.

The Embed Builder on this site generates this exact syntax visually with a live preview, if you'd rather not write it by hand.

Variables

Placeholders like {user.mention} that get replaced with real values wherever scripting is supported - welcome/leave/boost/join DM messages, ticket panels, reaction roles, and ,createembed.

Grouped by category: Guild, User, Channel, Ticket, Twitch, YouTube, Leveling, and more - each with the exact placeholder text and an example of what it resolves to.

See the full, categorized list on the Variables reference page.

Permissions

Most commands check for a real Discord permission before running - whichever permission a command needs is shown on its card on the Commands page. The common ones you'll see referenced throughout this documentation:

Administrator, Manage Guild, Manage Roles, Manage Channels, Manage Messages, Manage Nicknames, Manage Webhooks, Manage Guild Expressions, Ban Members, Kick Members, Moderate Members, View Audit Log, Mention Everyone, Attach Files, Embed Links.

You can also disable individual commands per server with ,disable - server-wide, or scoped to a specific channel or role - and bring them back with ,enable. And Fake Permissions let you grant access to a blaid command without the real Discord permission behind it.
